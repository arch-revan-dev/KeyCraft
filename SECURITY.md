# Безопасность и приватность (Zero-Keylogger Architecture)

KeyCraft работает с системным перехватом ввода — поэтому прозрачность и безопасность являются базовыми архитектурными инвариантами проекта.

## Архитектурные гарантии

1. **100% офлайн, 0 сетевых запросов:**
   - В рантайм-дереве зависимостей `keycraft` отсутствуют HTTP/WebSocket-клиенты (`reqwest`, `hyper`, `ureq`, `surf`, `isahc`).
   - В `src-tauri/tauri.conf.json` задан строгий CSP, разрешающий исключительно встроенные ассеты, локальный внутрипроцессный IPC (`ipc: http://ipc.localhost`) и in-memory протокол скриншотера (`keycraft-capture:`).
   - Отсутствуют телеметрия, аналитика, отправка краш-дампов и фоновые проверки обновлений.
2. **RAM-only буфер с принудительной очисткой (`zeroize`):**
   - Текущее слово хранится только в оперативной памяти (максимум 64 символа).
   - Буфер немедленно перезаписывается нулями (`zeroize`) при пробеле, клике мыши, смене активного окна, навигационных клавишах, паузе или выходе.
   - Вводимый пользователем текст **никогда** не записывается в файлы, логи или конфигурацию.
3. **Защита полей ввода паролей:**
   - Выделенный поток `UIAutomation` отслеживает `UIA_IsPasswordPropertyId` и системные эвристики защищённых полей.
   - При фокусе на поле пароля буфер немедленно затирается, а перехват ввода отключается до смены фокуса.
4. **Проверка целостности релизов:**
   - Каждый релиз на GitHub сопровождается файлом `SHA256SUMS.txt` для верификации бинарных файлов перед запуском.

## Сообщение об уязвимости

Если вы обнаружили проблему безопасности (например, обход детекции поля пароля в конкретном приложении или утечку буфера):

- Не публикуйте эксплойт в публичном Issue.
- Откройте приватный отчёт через вкладку **Security → Advisories → Report a vulnerability** в репозитории GitHub.
- Укажите версию Windows/ОС, целевое приложение и минимальные шаги воспроизведения.
